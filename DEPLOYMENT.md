# Saarthi deployment handoff

## Hosting plan

- **Netlify:** serves the static frontend from `frontend/` and proxies `/api/*` to the Render backend. No serverless backend is used.
- **Render:** runs the existing Dockerized Express backend. The blueprint uses a paid small web service plus a 1 GB persistent disk for car and inspection photos, with automatic deploys disabled.
- **MongoDB Atlas:** keep the existing M0 cluster for this small demo database.
- **Payments:** use Razorpay Test Mode only.

No hosting service has been created from this workspace. Applying `render.yaml` starts billable hosting. The current estimate for Render service plus disk is about **$7.25/month (roughly ₹675/month)** before taxes and card fees. Netlify and Atlas M0 are expected to remain on free tiers. Recheck vendor prices and your payment method's conversion/fees before ordering. Do not enable auto-recharge or upgrade Netlify.

## Prepared files

- `netlify.toml`: publishes `frontend/` and proxies `/api/*` to a placeholder Render hostname. After Render creates a hostname, replace `SAARTHI-RENDER-SERVICE` with the hostname only, for example `saarthi-api.onrender.com`; keep `https://`, `/api/:splat`, and the rest of the rule unchanged.
- `render.yaml`: Docker backend service, `/api/health` check, a 1 GB persistent disk, secrets supplied manually, and auto deploys turned off.
- `Dockerfile`: packages the existing backend and frontend for Render.
- `.dockerignore`: excludes dependencies, `.env`, uploads, Git metadata, and the duplicate `frontend/frontend` tree.
- `backend/.env.example`: placeholder local configuration only. The real `backend/.env` is ignored by Git. Never commit it or share its contents.

## Render environment values

The blueprint expects:

- `NODE_ENV=production`
- `JWT_SECRET`: generated by Render
- `MONGODB_URI`: Atlas connection URI using a dedicated Saarthi application database user with only required read/write access
- `SAARTHI_UPLOAD_DIR=/var/lib/saarthi/uploads`
- `TRUST_PROXY_HOPS=2`: verify against Render's current trusted proxy chain before relying on client-IP rate limits
- `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`: Test Mode values only
- `RAZORPAY_WEBHOOK_SECRET`: separate secret generated for the Test Mode webhook
- `GEMINI_API_KEY`: needed for AI features; provider quotas or charges may apply, so check account pricing/limits before enabling it

Render services use shared regional outbound IP ranges. After the service exists, open its Render dashboard Connect > Outbound and add the Singapore CIDR ranges to Atlas Network Access. These are shared ranges, not exclusive to this service. Dedicated outbound IPs require an additional paid plan and are outside this demo budget. Avoid Atlas 0.0.0.0/0 if possible; Atlas warns that it allows access attempts from anywhere. Use the dedicated least-privilege database user and strong credentials.

## Manual deployment steps — wait until ready for the recurring cost

1. **Review/accept the billable Render service and persistent disk.** Do not apply the blueprint until you are ready for roughly ₹675/month plus applicable charges.
2. In Render, create a new Blueprint from the repository and inspect the plan/disk in the review screen before confirming. Keep automatic deploys off.
3. Enter the Atlas URI and provider secrets in Render's secret fields only. Never paste secrets into Git, Netlify, chat, or this document.
4. Wait for Render to finish deploying. Open `https://<render-host>/api/health`; it must report ready with MongoDB connected and upload storage writable.
5. Edit `netlify.toml`, replacing the placeholder hostname with Render's exact service hostname. Commit/push this configuration change, then let the connected Netlify project deploy it. Keep the Netlify site private and stay on Free with auto recharge disabled.
6. Check the Netlify site and exercise login, browsing, small car photo upload, booking, inspection photo upload/readback, AI features, and Razorpay Test Mode. Do not use real payments.
7. In Razorpay Test Mode, optionally configure `/api/payments/webhook` and place its separate webhook secret in Render. Test provider events using test data only.
8. Stop the Render service when the demo period ends, then verify the service and disk are removed if you want recurring charges to stop. Review the provider's billing screen for final charges.

Never switch to Razorpay Live Mode, publish the private Netlify site, add paid upgrades/domains, or enable auto recharge without deciding separately.

## Limitations and checks

Render persistent disk is required: production health fails when upload storage is absent/unwritable. Atlas M0 is small and intended for prototypes. AI provider availability and quotas depend on the Gemini account. Rate limits are in memory and do not coordinate across multiple app instances. This hosting arrangement is intended for a small class demonstration, not production customer traffic.

Local checks: start with `npm start`, then run `npm test` and `npm --prefix backend run smoke`. The current test suite result recorded during preparation is **110 passed, 0 failed**. Docker is not installed in this workspace, so the container build has not been run here. Once hosting exists, set `SMOKE_BASE_URL` to the Netlify HTTPS site and run the smoke script; then manually test critical user workflows. No deployed end-to-end check has been completed because the Render hostname does not exist yet.
